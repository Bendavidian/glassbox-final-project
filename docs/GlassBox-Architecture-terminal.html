GlassBox Trader

An explainable algorithmic paper-trading system, and a study run on it. This deck is the architecture and every external component it uses.

The study's result is a measured null: three published forecasting architectures extract nothing from daily closing prices that they do not also extract from white noise. The finding rests on a control that degrades exactly where its mechanism predicts it must, which is what distinguishes a null result from a disconnected pipeline.

Contract 1 — data flows strictly upward

experiments → backtest → dashboard
   → explain → engine → model
   → features → data
   → contracts → config

Contract 2 — the live path never imports the harness

source     live_loop, replay, records
forbidden  backtest, experiments
Enforcement is doubled: the tool runs in CI, and tests/contracts/test_layers.py runs it in-process and asserts both contracts are still configured. Deleting a contract from the config turns the suite red rather than silently reducing coverage.
The second contract exists because of records.py specifically. It holds the live trade log, so it is the module most tempted to import backtest.engine.Trade — that type moved to contracts/schemas.py instead.

The reference project: what was refusedThe audit records refusals as well as permissions, with the reason measured rather than asserted.

utils/metrics.py — unusable. backtest/metrics.py was written from scratch.

SHARP()returns a hardcoded 12
SHARP2, SHARP5each defined twice, the second shadowing the first
one variantcontains pred = true + 0.01 — the prediction is overwritten with ground truth

strategies.py

All four stop and target comparisons inverted. The audit lists each correct form; backtest/engine.py cites it, and the four cases each carry an explicit test.

Explicitly not a bug

moving_avg pads both ends, making the trend a centred average. That is correct inside the input window, all of which precedes the forecast. Centring remains forbidden in the feature layer.

Anyone can list what they used. A reasoned refusal to use broken code — with the defect named, the correct form derived independently, and a test pinning each case — is evidence that the reference was read rather than copied. pred = true + 0.01 would have produced a backtest that looked extraordinary and meant nothing.

The three modelsThree different lineages, stated separately rather than in one word.

modelparameterslineage
DLinear4,800LTSF-Linear (Zeng et al., AAAI 2023). Two lineages: the decomposition is adapted from the reference implementation; the two linear heads are reimplemented and depart from the paper as well
FITS1,200FITS (Xu, Zeng & Xu, ICLR 2024). Original implementation from the paper's description. No reference source exists in this repository
WITS882Original. No paper, no reference. Built to test whether FITS's data-independence is a property of extending a global basis or of FITS specifically
persistence0the zero-return baseline

The decomposition — adapted

A centred moving average with edge replication, kernel 25: same algorithm, same constant, rewritten from torch to numpy. Edge replication is an implementation choice rather than a mathematical one — the paper does not say which padding to use — so this is code-first provenance and is recorded as such. One identifier survives the rewrite.

The two heads — reimplemented

  1. Per-channel weights, not shared
  2. No intercept — a bias would break exact attribution
  3. Zero initialisation — the default bound is wrong for C×2 summed maps
  4. One summed output series; torch fits, numpy predicts
The decomposition block predates the reference project: the same moving_avg / series_decomp pair appears in LTSF-Linear's released source and, to our knowledge, in Autoformer before it. The audit records our proximate source, which is the reference project. WITS's prediction was pre-registered, written into the expansion plan before a line of the model existed.

yfinancehistorical daily bars, adjustedper-symbol, never bulk. The cache is authoritative: a stale file is returned unchanged unless forced, so the study runs against a fixed snapshot
Alpaca Datalive daily bars, identical schemafeed hardcoded to SIP with no fallback — IEX measured wrong by up to 193 bps against a 1 bp tolerance. No cache: a cached bar in a trading decision is a stale price
Alpaca Tradingorders, positions, accountpaper only. A guard refuses any non-paper base URL before any call is made. Both clients share a 45 s read timeout
GitHub RESTCI run statusdevelopment tooling only, not inside the package
Credentials live in a gitignored .env with a committed template, and a test scans every tracked file for credential-shaped strings — written after a real paper key reached a local commit. The 45 s timeout exists because of a 90-minute stall: no HTTP read had one, since the SDK takes no timeout parameter, and the retry policy bounds the number of attempts and not their duration.

Disclosure statementEverything external, in one place.

  • 13 runtime and 6 development dependencies, each pinned, each with a dated entry recording why it was added.
  • One reference project, read-only and excluded from the build by three independent mechanisms. What was taken and what was refused is recorded in REFERENCE_AUDIT.md, written before the code.
  • Two published architectures. DLinear's decomposition adapted from the reference and its heads reimplemented with four documented departures; FITS written from the paper's description with no source implementation available. WITS is original.
  • Four external services. Alpaca paper only, enforced before any call. No service is called from inside the package without its constraint encoded beside it.
  • Built with Claude Code, recorded in 130 of 132 commit trailers, an operating contract in the repository root, and 1,572 lines of session prompts.
Nothing else external is used. No file in glassbox/ carries a "copied from" or "adapted from" header. Persistence, the feature builder, the causality harness, the sweep harness, the executor, the reconciler, the live loop, the console and the explain layer are original.
Full detail with file and line citations: docs/ARCHITECTURE_INVENTORY.md. The claim above is stated about the repository rather than about intent, so it can be checked against the tree.
